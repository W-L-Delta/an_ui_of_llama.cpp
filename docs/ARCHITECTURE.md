# 架构

## 组件

```
┌─────────────────────────┐        HTTP (127.0.0.1)
│ chat-app/llama-chat.exe │  ───────────────┐
│ WinForms + WebView2     │                 │
│  └─ 加载 /chat 页面      │                 ▼
└───────────┬─────────────┘      ┌──────────────────────┐
            │ 进程内启动           │ panel/app.py (8090)  │
            ▼                     │  · 配置读写           │
   ┌──────────────────┐           │  · 会话持久化         │
   │ panel/app.py     │           │  · 工具执行器         │
   │ (子进程)          │           │  · 静态资源 /chat     │
   └──────────────────┘           └──────────┬───────────┘
                                             │ HTTP
                                             ▼
                                  ┌──────────────────────┐
                                  │ llama-server (8080)  │
                                  │  · OpenAI 兼容 API    │
                                  └──────────────────────┘
```

三个进程，职责清楚：

| 进程 | 角色 |
|---|---|
| `llama-chat.exe` | 原生窗口外壳；负责起面板、确保模型在跑、窗口外观（暗色标题栏、图标、窗口位置） |
| `pythonw app.py` | 控制台后端 + 静态文件服务 + 工具执行；**唯一**读写配置和会话的地方 |
| `llama-server.exe` | 推理服务，OpenAI 兼容接口 |

## 数据流

**发一条消息**：

1. 页面把 `conv.messages` 加上系统提示词、模型提示词、历史摘要、工具定义，POST 到 8080
2. 模型流式返回；若返回 `tool_calls`，页面逐个调用面板的 `/api/tools/exec`
3. 面板校验权限与路径，执行工具，把结果回传页面
4. 页面把工具结果作为 `tool` 消息塞回请求，进入下一轮，直到模型给出正文
5. 每轮结束把 `usage` 记进会话的 `ctxUsed`（上下文环的数据来源）

**改一个参数**：控制台 → `POST /api/apply` → 写入 `llama.conf.ini`（先备份）→ 停止旧进程 → 按新参数重启 → 轮询 `/health` 就绪。

## 关键设计

### 配置只有一份

`scripts/llama.conf.ini` 是唯一配置源：

- 启动脚本读它拼命令行
- 控制台读写它（每个模型一个段）
- 对话程序只读 `/api/state` 的派生结果（不直接碰文件）

### 参数按模型分段落

```ini
[gpu]        # base（Qwen3.5-9B）
ctx_size = 163840
[ qwen36 ]   # 覆盖同一组键
ctx_size = 65536
extra_args = --cpu-moe
```

启动时按「模型段 → 全局段 → 内置默认」三级回退，所以只写差异即可。

### 工具调用的信任边界

工具执行**不经过模型**，全部在面板进程里：

- 权限：会话级 `off / read / write / full`，服务端也有一道上限（`[tools] ceiling`）
- 路径：`resolve()` 后必须落在 `[tools] workspace` 内
- 审批：写操作与命令在执行前拦一道 UI 确认，可记住「本会话同类放行」
- 联网：SSRF 白名单式校验 + 逐跳重定向检查 + 结果相关性打分

### 前端不做持久化

页面把状态整份 POST 给 `/api/sessions`，面板原子写入（临时文件 → `os.replace`），
写之前留快照到 `panel/data/backups/`。

### 无窗口启动

任务计划程序启动控制台程序时会先分配一个控制台窗口（即使 `-WindowStyle Hidden` 也会闪一下）。
解决办法是让**任务动作本身**是 GUI 子系统程序：`windowless-runner.exe`（PE subsystem = 2）
以 `CREATE_NO_WINDOW` 拉起 `powershell.exe`，全程不创建控制台。

## 进程与计划任务

| 计划任务 | 作用 |
|---|---|
| `llama-keepalive` | 每 3 分钟 `start-llama.ps1 -EnsureRunning`，服务挂了自动拉起 |
| `llama-chat`（可选） | 让对话程序脱离调用者进程树启动，避免被连带杀掉 |

## 看门狗与自愈

- 外壳每 15 秒 ping 一次 `/api/state`，连续 2 次失败就重新拉起面板
- 面板写会话前备份，最多保留 30 份
- 保活任务检测到 `llama-server` 不在就重启
